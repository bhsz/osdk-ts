DocumentViewer

Beta — exported from @osdk/react-components/document-viewer.

Usage​

DocumentViewer takes an OSDK Media object, detects its MIME type, and renders it with the matching viewer.

Note — @my/osdk is a placeholder for your generated SDK package (e.g. @your-app/sdk). Replace it with the actual package name in your project.

import { DocumentViewer } from "@osdk/react-components/document-viewer";

function TrainingMaterial({ employee }) {
  return <DocumentViewer media={employee.trainingMaterial} />;
}

PDF, image, video, and TIFF rendering accept their own options via a pass-through prop (pdfViewerProps, imageViewerProps, videoViewerProps, tiffViewerProps). Only the prop matching the resolved viewer is applied. The markdown, spreadsheet, email, and XML viewers render with their defaults — to configure those, use the standalone viewer directly.

<DocumentViewer
  media={myMedia}
  pdfViewerProps={{ defaultSidebarOpen: true, enableDownload: true }}
  imageViewerProps={{ alt: "Product photo" }}
/>

When the MIME type is missing or ambiguous, hint the format with mimeTypeOverride or fileName.

<DocumentViewer media={myMedia} mimeTypeOverride="application/pdf" />

Style API​

DocumentViewer exposes its appearance through --osdk-* CSS variables, so you can theme it by overriding tokens without forking the component. The root container reads two tokens:

VariablePurpose
--osdk-document-viewer-bgViewer background
--osdk-document-viewer-borderViewer border

Each per-format viewer carries its own token group — --osdk-pdf-viewer-*, --osdk-image-viewer-*, --osdk-video-viewer-*, --osdk-markdown-viewer-*, --osdk-spreadsheet-viewer-*, --osdk-email-viewer-*, and --osdk-xml-viewer-*. See the CSS Variables reference — in particular the Document Viewer, PDF Viewer, and Markdown Viewer sections — for the full list of tokens and their defaults.

Standalone OSDK media viewers​

DocumentViewer is the entry point most consumers need — it picks the viewer for you. Reach for a standalone viewer when you already know the format, when you want to configure a viewer DocumentViewer renders with defaults (markdown, spreadsheet, email, XML), or when your source is not an OSDK Media object.

Each format ships two components from its own subpath:

  • <Format>Viewer — the OSDK-aware component. Takes a media: Media prop and handles fetching and decoding.
  • Base<Format>Viewer — the OSDK-agnostic component. Takes an already-resolved src (binary source: URL or bytes) or content (decoded payload), so you can drive it from your own data source.

Import subpaths below are relative to @osdk/react-components/.

PdfSource is string | ArrayBuffer | Uint8Array | Blob — a URL or raw bytes.

Anything not in the table above — .doc/.docx, for instance — resolves to ViewerType.Unsupported, and DocumentViewer renders a fallback message naming the MIME type.

// Standalone: you know the format, and want to configure it
import { SpreadsheetViewer } from "@osdk/react-components/spreadsheet-viewer";

<SpreadsheetViewer media={report.attachment} />;
// Base: your source is not an OSDK Media object
import { BaseXmlViewer } from "@osdk/react-components/xml-viewer";

<BaseXmlViewer content={xmlString} />;

Advanced​

DocumentViewer has no base component or headless hooks of its own to compose — it is a dispatcher. Customize the resolved viewer through the pass-through props in the Props table (pdfViewerProps, imageViewerProps, videoViewerProps, tiffViewerProps), each of which forwards its object to the matching viewer. For the formats without a pass-through prop, render the standalone viewer instead.

PdfViewer is the one viewer with a headless tier: the pdf-viewer subpath also exports hooks such as usePdfDocument, usePdfOutline, usePdfAnnotationsByPage, and usePdfViewerSync for building a custom PDF surface. See the PdfViewer reference.

The package also exports the ViewerType enum, which enumerates what DocumentViewer can resolve to (Pdf, Tiff, Image, Video, Markdown, Spreadsheet, Email, Xml, Unsupported) — useful for identifying or asserting which viewer a given MIME type maps to.
